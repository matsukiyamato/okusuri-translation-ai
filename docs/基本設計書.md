# 基本設計書 

## 1. 全体アーキテクチャ設計
本システムは、React Native (Expo) によるフロントエンド、FastAPIによるバックエンド、ChromaDBを用いたRAG、およびModel Context Protocol (MCP) を介した外部公的医療情報源（PMDA）の連携によって構成される。

### 1.1 システムコンポーネント図
```text
[フロントエンド: React Native / Expo]
       │ (HTTPS / JWT)
       ▼
[バックエンド: FastAPI (Python 3.11)]
       ├── [API Rate Limiter / Circuit Breaker] (無料枠超過時のシステム自動停止制御)
       ├── [Security / Policy Filter] ── (Argon2id / AES-256-GCM / 医療ガードレール)
       ├── [Google Cloud Vision API] (OCR処理、画像即時削除)
       ├── [FastMCP Client] ── (MCP Protocol) ── [PMDA MCP Server] (外部公的DB)
       └── [LangChain / ChromaDB (RAG)] ── [Gemini 2.5 Flash] (JSON構造化・やさしい日本語変換)
```
---
## 2.データベース設計
　MySQLを使用し、ユーザーのアイデンティティとインターフェイス選択ステートをセキュアに管理する。

### 2.1 usersテーブル設計

**暗号化・セキュリティ要件：**
- encrypted_email は、個人情報保護（D-02）に基づき、**AES-256-GCM**を用いて暗号化したバイナリデータを永続化する。
- password_hash は、Argon2idアルゴリズムを強制適用して生成した文字列を格納する。 

| 論理カラム名 | 物理カラム名 | 型 | 制約 | 説明 | 
| --- | --- | --- | --- | --- |
| ユーザーID | id | VARCHAR(36) | PRIMARY KEY | システム内部管理用のUUID |
| Google一意ID | google_sub | VARCHAR(255) | UNIQUE NOT NULL | Google認証から返却されるアイデンティティ確認キー |    
| 暗号化メールアドレス | encrypted_email | VARBINARY(255) | UNIQUE NOT NULL | AES-256-GCMにより暗号化されたメールアドレス |
| パスワードハッシュ | password_hash | VARCHAR(255) | NULL許容 | Argon2idでハッシュ化。仮登録ステート時はNULL |
| ユーザーUIモード | interface_mode | ENUM('text_audio', 'sign_language') | NULL許容 | text_audio(テキスト・音声) / sign_language(手話動画)。初回時はNULL。 |
| レコード作成日時 | created_at | DATETIME | NOT NULL | 仮登録および本登録の開始起点日時 |
| レコード更新日時 | updated_at | DATETIME | NOT NULL | UIモード変更またはパスワード設定時の更新日時 |

### 3.アプリケーション画面遷移・UI設計(フロントエンド)
　React Native (Expo SDK 56) を用い、アクセシビリティ（AccessibleText / AccessibleButton、48x48dp以上のタップ領域）を担保した共通コンポーネントを基底に配置する。

## 3.1 画面一覧と制御ロジック

 **1. ユーザー登録画面(UserRegistrationScreen)**

  **制御**：メールアドレス・パスワード入力フォーム、および「Googleで新規登録」ボタンを配置。Google OAuthを実行し、成功時は仮登録レコードを生成させ、自動的に「2. パスワード追加設定画面」へ遷移する。

 **2. パスワード追加設定画面 (PasswordSetupScreen)**

 **制御**：画面遷移時に仮登録用のセットアップトークン（有効期限10分、SETUP_JWT_SECRET で署名）を保持。Googleから取得したemailを「読み取り専用（Disabled）」として自動入力。右側に可視化トグルボタンとアイコンを配したパスワード入力フォームを実装。

 **3. ログイン画面(UserLoginScreen)**

 **制御**：通常のローカル認証（メール/パスワード）およびGoogle認証の入口を完全に分離して提供。認証成功時に正規のセッションJWT（JWT_SECRET で署名）を取得・保持する。

 **4. モード選択画面 (ModeSelectionScreen)**
 
 **制御**：認証成功後の初回遷移（interface_mode がNULLの場合）に強制遷移。属性差別を排除するため、ラジオボタン形式で出力形式（テキスト・音声 / 手話動画）のみを選択させる。

 **5. 注意書き画面 (ScanGuidanceScreen)**

 **制御**：L-03要件である「本システムは医療情報の理解支援を目的としており、診断・治療・処方・服薬判断を行うものではありません。」等の免責事項を明示的なスクロールUIで提示。撮影のコツ（明るい場所、枠組みへの合わせ方）とお手本動画（GIF）を表示。

 **6. スキャン画面 (CameraCaptureScreen)**

 **制御**：カメラAPIを起動し、薬剤情報提供書を合わせるための「枠組み（オーバーレイ）」をUI上に常時表示。

 **7. スキャン内容確認画面 (OcrVerificationScreen)**

 **制御**：上部にスキャンしたプレビュー画像、下部にOCRおよびGemini Flash 2.5によって構造化された薬剤名・生テキストを表示。要件定義書記載の「AI誤認識対策」に基づき、OCRの誤認識に備えてユーザーが手動でテキスト修正・確定を行えるフォーム、および「再撮影」へ戻るための制御トリガーボタンを実装する。

 **8. 薬の翻訳画面：テキスト・音声 (TextAudioResultScreen)**

 **制御**：interface_mode == 'text_audio' の場合に遷移。平易な日本語テキスト、および厳格な出典情報（出典名、URL、最終更新日、参照日次）を表示。Google TTSによる自動読み上げ制御コンポーネントを設置。

 **9. 薬の翻訳画面：手話動画 (SignLanguageResultScreen)**

 **制御**：interface_mode == 'sign_language' の場合に遷移。画面中央に手話動画プレイヤー、下部に字幕（バックアップテキスト）を表示。追加の音声質問時（Google STT起動時）、AI誤認識対策として「認識結果のテキスト表示」と、ユーザーが内容を確認して「再入力」または「確定」を選択できる対話型UIを設置する。

### 4. バックエンドAPIエンドポイント・ビジネスロジック設計 (FastAPI)
 すべてのレスポンスは、Pydanticによる厳格な型定義と、**ハルシネーション**を防止するためのJSONスキーマ検証（N-11）を行う。

## 4.1 認証・認可 API

ハッカーによるリバースエンジニアリングやトークン偽造を防止するため、2つのJWTは異なる鍵で署名し、必要最低限のクレーム（データ）のみを内包させる。内部システムのUUID等の識別子は一切露出させない。

**① Google OAuth コールバック**
 **パス**：/api/v1/auth/google/callback (GET)
 **ロジック**：
 Google認証から google_sub および email を取得。新規ユーザーの場合、email をAES-256-GCMで暗号化して encrypted_email に格納し、password_hash = NULL でMySQLへインサート（仮登録状態）。有効期限10分の SETUP_JWT_SECRET で署名した一時セットアップトークンを発行してフロントエンドへ返却。

**② パスワード追加設定**
 **パス**：/api/v1/auth/register/setup-password (POST)
 **ロジック**：
  SETUP_JWT_SECRET を検証。入力パスワードをArgon2idでハッシュ化し、対象レコードの password_hash をUPDATE（本登録完了）。すでに password_hash が存在する（本登録済み）レコードからの要求は二重登録防止として400 Bad Requestで即時拒否。

**③ ローカル認証ログイン**
 **パス**：/api/v1/auth/login (POST)
 **ロジック**：
 入力されたメールアドレスを暗号化して照合し、password_hash を比較検証。
　→**安全ガードレールロジック**:
一致するレコードが存在しても、password_hash IS NULL（仮登録状態）のユーザーは、ローカルログインを即時拒否・完全遮断する

**④ データライフサイクル管理（ゴミデータ自動消去タスク）**
 **ロジック**: 
 backend/services/auth_lifecycle.py に常駐またはcron/Celery等によるバックグラウンドバッチタスクとして実装。created_at から24時間以上経過、かつ password_hash IS NULL のまま離脱している仮登録レコードを、毎日自動で一括物理削除（DELETE）する

**⑤ 仮登録用セットアップトークン(SETUP_JWT_SECRET)**
 **有効期限**：10分 (再利用不可、本登録エンドポイント専用スコープ)
 **ペイロード構造**：
 ```text
 Json
 {
  "iss": "okusuri-translation-ai-backend",
  "sub": "tmp_registration_session",
  "exp": 1783214400, 
  "scope": "user:complete_registration",
  "h_mail": "メールアドレスのSHA-256ハッシュ値（レコード特定用の一致検証キーとして使用）"
}
 ```
**⑥ 正規セッションJWT (JWT_SECRET)**
 **有効期限**：24時間
 **ベイロード構造**：
 ```text
 {
  "iss": "okusuri-translation-ai-backend",
  "sub": "authenticated_session",
  "exp": 1783297200,
  "scope": "user:standard_access",
  "usr_mode": "text_audio" 
}
 ```

## 4.2 OCR・構造化・RAG 処理パイプライン API
**① 薬剤説明書解析**
 **パス**：/api/v1/ocr/analyze (POST)
 **ロジック**：
  1. 受信した画像を Google Cloud Vision API へ転送し、文字情報を抽出（OCR）。
  2. プライバシー保護要件 (D-01): 処理完了直後、アップロードされた画像データをサーバー上から即時完全削除する。
  3. 抽出テキストを Gemini 2.5 Flash に入力し、薬剤名や用量等をJSON構造化データに変換（JSON Mode強制）。

**② 公的医療情報連携層 (MCP)**
 **ロジック**: backend/mcp/client.py
　→最新の Model Context Protocol (MCP) 仕様に準拠し、FastMCP クライアントを介して外部の PMDA Connector（患者向医薬品ガイド MCP、添付文書 MCP）にリアルタイム接続。当該薬剤の正確な公式ドキュメントを動的に引き当てる。

**③ RAG (検索・生成)・やさしい日本語変換**
 **パス**: /api/v1/rag/translate (POST)
 **ロジック**: backend/services/rag_service.py
  →LangChain を用いて、OCRテキストとMCPから得た公的医療情報をコンテキストとして抽出し、ChromaDBのベクトルインデックスと照合。
  ・**フォールバック機能 (F-14)**: ネットワークエラー等で外部PMDAへの接続が失敗した場合は、自動でローカルのVector DB（キャッシュ/あらかじめ同期された公的医療情報）を利用する切り替えロジックを実行する。
  ・**ハルシネーション防止 (L-10, L-11)**: 検索結果に存在しない情報は出力しない。検索結果が空の場合は回答を生成しない。Gemini 2.5 Flash を用い、ファクト情報のみを「やさしい日本語」へコンテキスト変換する。
  ・**出典の固定表示 (L-07)**: すべての応答テキストの末尾に、以下の形式のメタデータを強制付与する。出典が付与できない回答はシステムレベルで出力を禁止（拒否）する。
 
**Json形式（例）**：
```bash
{
  "output_text": "...",
  "reference": {
    "source_name": "出典名（例: PMDA 患者向医薬品ガイド）",
    "url": "参照元URL",
    "last_updated": "データの最終更新日",
    "retrieved_at": "アプリ側でのシステム参照日時"
  }
}
```

## 4.3 音声認識・合成 & 手話動画ビジネスロジック API

**① 安全ガードレール付き双方向音声対話**
**パス**：/api/v1/voice/query (POST)
**ロジック**：
 1. ユーザーの音声質問（Google STTによりテキスト化）を入力として受ける。
 2. **医療ポリシーフィルタ（医療・法令対応ガードレール）**: 
    backend/utils/security.py 内の検知関数により、入力テキストを検証。**診断、治療提案、服薬継続/中止判断、投薬判断、飲み合わせ判定、受診要否判定、緊急性判定、個別患者へ**の**医療助言**に該当するキーワードまたはコンテキストを検知した場合、RAG検索をスキップし、ポリシー拒否メッセージを安全に返却する（例：「本システムは医療判断を行えません。医師または薬剤師へご相談ください。」）。
 3. フィルタを通過した質問のみ、MCP/RAG経由で出典付き回答を生成する。
 4. **音声出力安全パイプライン制御 (要件22)**: Google TTS（音声合成）へデータを引き渡す際も、バックエンドのロジック層でポリシーフィルタおよびガードレール機能を厳格に挟み、**「出典付き回答のみ」**を安全に読み上げる実行パイプラインをプログラムレベルで徹底する。

**② 手話辞書管理・動的指文字マッピング**
 **パス**: /api/v1/dictionary/sign-language (GET)
 **ロジック**: backend/services/sign_service.py  
    変換された「やさしい日本語」の単語に対応する手話動画（音声・字幕付き、当事者視点で裏取りの上、CapCutで自作・編集された肖像権等に配慮した動画データ）をデータベースから検索。  
 **動的指文字マッピングロジック (F-15)**: 物理的に薬剤を示す固有の手話表現（単語）が辞書データベースに存在しない場合、システムが自動的にその単語を50音（あ、い、う、え、お）に分解。対応する「指文字動画」をプログラム的に動的にマッピングし、シームレスに結合・再生するビデオストリームを構成してフロントエンドへ提供する。  

# 4.4 API従量課金超過に伴う自動システム停止ミドルウェア**
 すべての外部有料API呼び出し（Gemini, Vision, STT, TTS）の破産的課金を防ぎ、無料枠の範囲内で安全にポートフォリオ運用を行うため、FastAPIのミドルウェア層にサーキットブレーカーを実装する。
 **ロジック**: backend/app/middleware/rate_limiter.py
 →Redisまたはローカルインメモリキャッシュを用い、当月/当日のAPIリクエスト総数をカウント。
 →設定された無料枠の上限値（例: Google Cloud無料枠の80%に相当するリクエスト数）に達した場合、内部フラグ CIRCUIT_BREAKER_ACTIVE = True を起動。
 →以降の該当API要求に対し、外部へのリクエストを遮断し、フロントエンドへ一律で 503 Service Unavailable (Message: API利用枠制限によるシステム一時停止中) を返却して従量課金の発生を物理的・自動的に防止する

### 5. コンプライアンス・セーフティ設計 (SaMD非該当の担保)
　本設計は、厚生労働省の「医療機器プログラム（SaMD）ガイドライン」に抵触しないよう、以下の原則（L-12）をコードおよびシステム構成レベルで物理的に固定化する。

 1. **能動的医療判断の完全排除**:
  システムが独自のアルゴリズムや確率論に基づいて、個別患者の症状に対する「投薬の最適性」「飲み合わせの危険性」「受診の必要性」を判定・出力するコード（ロジック）はバックエンドの一切のモジュールに記述してはならない。
 2. **既存情報の変換と表示に限定**:
  LLM（Gemini 2.5 Flash）の役割は、**PMDA**から取得した「**既存の公的医療テキスト**」を「**言語的アクセシビリティ（やさしい日本語）**」「**身体的アクセシビリティ（音声・手話動画）**」へ**構造・表現の変換**を行うことのみに限定する。
