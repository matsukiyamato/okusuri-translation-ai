### バックエンド処理詳細定義書
本ドキュメントは、「お薬翻訳AI」のバックエンド（FastAPIスタック）開発における全エンドポイントの内部ロジック、データフロー、セキュリティガードレール、および外部API・データベース連携の挙動を徹底的に網羅した実装メモである。

---

### 1. 共通基盤・セキュリティ処理定義

## 1.1 認証・登録ライフサイクルパイプライン

本システムは安全性を担保するため、Google OAuth認証からローカル認証（パスワード設定）へ至る「2フェーズ登録」を採用する。

```Plaintext
[Google OAuth Callback]
  │ (OAuth検証)
  ▼
[一時セットアップ用JWT発行] (有効期限10分 / SETUP_JWT_SECRET署名)
  │
  ▼
[パスワード追加設定 (UPDATE)] (Argon2idハッシュ化 & users永続化)
```

**① Google OAuth コールバック (/api/v1/auth/callback)**

 **1. OAuthトークン検証**: 
 フロントエンドから受け取った認可コード、またはExpoの認証セッションから渡されたトークンを用いてGoogle APIから email を取得する。

 **2. Email暗号化**: 

    取得した email（平文）を backend/utils/security.py 内の encrypt_email() に通し、環境変数 AES_ENCRYPTION_KEY_HEX（64文字の16進数文字列）からデコードした鍵を用いて AES-256-GCMで暗号化、バイナリデータ（bytes）に変換する。

 **3. DB照会・仮登録ステート生成**:

    暗号化された encrypted_email をキーに MySQL の users テーブルを検索する。

    レコードが存在しない場合：新規の UUID v4 を id として生成し、encrypted_email、password_hash = NULL、interface_mode = NULL の状態で users テーブルに INSERT する（仮登録ステート）。
 **4. セットアップトークン発行**:

    ユーザーID（id）をペイロードに含め、環境変数 SETUP_JWT_SECRET を用いて署名した有効期限10分の一時的セットアップJWTを発行し、フロントエンドに返す。

**② パスワード設定・本登録 (/api/v1/auth/setup-password)**

 **1. トークン検証**: 

    リクエストヘッダーの Authorization: Bearer <TOKEN> からセットアップトークンを抽出し、SETUP_JWT_SECRET で検証して id を取り出す。

 **2. パスワードのハッシュ化**: 

    フロントエンドから送信されたパスワード文字列を、argon2.PasswordHasher(time_cost=3, memory_cost=65536, parallelism=4) を用いて Argon2id プロファイルでハッシュ化する。
 
 **3. 本登録永続化**: 

    users テーブルの該当 id レコードに対し、生成したハッシュ文字列で password_hash を UPDATE する。
 
 **4. セッションJWT発行**: 

    通常のセッション用JWT（環境変数 JWT_SECRET で署名、有効期限：任意）を発行し、フロントエンドへ返す。

## 1.2 不完全な仮登録データの自動物理削除バッチ
 
 **実行契機**: 
    24時間ごとにバックグラウンドで実行（APScheduler または FastAPIの RepeatEvery タスク）。
```SQL
DELETE FROM users 
WHERE password_hash IS NULL 
  AND created_at < NOW() - INTERVAL 24 HOUR;
```
    
    作成日時（created_at）から24時間が経過しても password_hash が NULL のまま（本登録未完了）のレコードを物理削除し、ストレージの圧迫と浮遊アカウントの蓄積を防ぐ。

### 2. コアビジネスロジック・処理フロー

## 2.1 OCR・構造化パイプライン (/api/v1/ocr/scan)

 **1. 画像受け取り**:
    フロントエンド（CameraCaptureScreen）から送信される画像データをマルチパートフォームデータ（UploadFile）としてパース。

 **2. Google Cloud Vision API 呼び出し**:             
    google-cloud-vision ライブラリを使用して画像をCloud Visionに送信し、TEXT_DETECTIONを実行して生テキスト（Raw Text）を抽出する。

 **3. 画像の即時削除原則 (D-01)**: 
    Cloud Vision APIへのデータ引き渡し、およびテキスト抽出のメモリ展開が完了した直後に、バックエンドサーバーのテンポラリ領域から画像ファイルを物理削除する（サーバー内に画像を一切永続化・残存させない）。

 **4. GeminiによるJSON構造化**:
    ・2026年推奨の最新SDKである google-genai を用いて client.models.generate_content を呼び出す。

    ・model="gemini-2.5-flash" を指定。

    ・config=types.GenerateContentConfig(response_mime_type="application/json", response_schema=OcrStructuredData) を設定し、以下のスキーマ構造に強制パースさせる。

 **5. レスポンススキーマ (OcrStructuredData)**:
```JSON
{
  "medicine_name": "ロキソプロフェンナトリウム錠60mg",
  "dosage": "1回1錠、1日3回",
  "raw_text": "抽出された全生テキスト..."
}
```
    パース結果をフロントエンド（OcrVerificationScreen）へ返却する。

 ## 2.2 医療ポリシーフィルタ（ガードレール）
すべてのフリーテキスト入力（追加質問 /api/v1/rag/ask など）に対し、LLM（Gemini）へコンテキストを渡す前にバックエンドのアプリケーション層で厳格な「ポリシー検知」を実行する。

- 禁止定義：診断、治療、処方、服薬・投薬の可否判断、併用リスクの断定など、医師・薬剤師の独占業務に該当する質問。

- 検知手法：
 1. キーワードマッチング（「飲み合わせ」「大丈夫」「副作用か」など）による一次トラップ。

 2. Gemini 2.5 Flashを用いたインラインジャッジプロンプト。

- 拒否応答の統一: 
    ポリシーに抵触したと判定された場合、RAG検索やGemini本体の生成処理を即座に遮断（ショートサーキット）し、固定エラーレスポンスを返す。

```JSON
{
  "status": "policy_violation",
  "message": "本システムは医療行為・医療診断を行えません。医師または薬剤師へご相談ください。"
}
```

## 2.3 RAG（検索拡張生成）パイプライン (/api/v1/rag/translate)
フロントエンドでユーザーが確定させた「薬剤名」を基に実行する、ハルシネーション（嘘の回答）を完全に排除した情報変換・生成フロー。

```Plaintext
[確定されたお薬名] ➔ メタデータフィルタ（medicine_name 一致）
                        │
                        ▼
            [ChromaDB ベクトル検索] (Cosine類似度)
                        │
                        ▼
            [公的医療テキスト片 (PMDA出典) 抽出]
                        │
                        ▼
            [Gemini 2.5 Flash] ➔ 「やさしい日本語」へ翻訳・変換
```
 1. メタデータフィルタリングの適用:

   ChromaDB コレクション（pmda_medical_knowledge）に対し、確定した medicine_name で厳格なメタデータ絞り込み（完全一致・前方一致フィルタ）を行う。

 2. ベクトル類似度検索:
   入力テキスト（または薬剤の基本コンテキスト）を text-embedding-004 を通して768次元ベクトル化し、コサイン類似度に基づいてChromaDBから上位K件（top_k=3）の関連文書チャンクを抽出する。

 3. プロンプトへのコンテキスト注入:
   抽出された文書（生テキスト）と、そのチャンクに紐づくメタデータ（source_citation: 「出典：PMDA」）を、生成用プロンプトのコンテキスト領域へ埋め込む。

 4. やさしい日本語の生成要件:
   ・専門用語の排除、文末の簡素化（「〜です」「〜ます」）、ルビを振りやすい単語構成。
   ・**客観的根拠の保持**:
   抽出したコンテキストに記載されていない「新たな効能・効果」や「独自の解釈」をGeminiが付け足すことをプロンプトインストラクションレベルで完全に禁止する（Temperature=0.0 を推奨）。

 5. レスポンス構造：
```JSON
{
  "translated_text": "この おくすりは、熱を 下げたり、痛みを 和らげたり する おくすりです。",
  "source_citation": "独立行政法人 医薬品医療機器総合機構（PMDA）公的データ"
}
```

## 2.4 手話辞書管理・動的指文字マッピング (/api/v1/dictionary/sign-language)
フロントエンドの手話動画モード（SignLanguageResultScreen）において、視覚的なアクセシビリティを提供するためのエンドポイント。

 **1. 形態素解析・単語分割**: 
   変換後の「やさしい日本語」のテキストを、バックエンド側で形態素解析（MeCab 等）を用いて単語単位に分割する。

 **2. 辞書照会（MySQL sign_dictionary）**:
   分割された各単語が、sign_dictionary テーブルの word カラムに登録されているかインデックス検索を実行する。
   →**登録がある場合**：
      該当する自作手話動画の video_url（字幕付き、CapCut編集済みオブジェクトストレージURL）を取得。

 **3. 動的指文字マッピング（バックアップロジック）**:
 単語が辞書に存在しない場合、プログラムが自動的にその単語を一文字ずつの50音（例：「ロ」「キ」「ソ」）に分解する。

 ・分解した各文字に対応する固定の「指文字ビデオクリップURL」をデータベース、または静的定義から動的にマッピングする。

 **4. プレイリスト配列の返却:**
   単語動画と指文字動画をシームレスに結合してフロントエンド側で連続再生できるよう、順序が保証されたURLの配列（PlayList）を作成してレスポンスする。
```JSON
{
  "playlist": [
    {"word": "ロ", "video_url": "https://storage/.../yubi_ro.mp4", "type": "finger"},
    {"word": "キ", "video_url": "https://storage/.../yubi_ki.mp4", "type": "finger"},
    {"word": "痛みを和らげる", "video_url": "https://storage/.../sign_itami.mp4", "type": "word"}
  ]
}
```
## 2.5 音声出力安全パイプライン制御

 ・Google Text-to-Speech（TTS）を用いた音声ストリーム生成時、フロントエンドから任意のテキストを直接受け付ける構造は厳禁とする。

 ・**制御ロジック**: バックエンドのビジネスロジック層において、前述の「2.2 医療ポリシーフィルタ」および「2.3 RAGコンテキスト抽出」の処理を完全に通過し、「**公的出典が保証されたやさしい日本語テキスト（translated_text）**」のみをシステム内部でTTSモジュールに引き渡す。これにより、悪意のあるインジェクションや、AIのハルシネーションによる誤った医療情報が音声として自動読み上げされるリスクをパイプラインレベルで遮断する。

### 3. 破産的課金防止対策（自動システム停止ミドルウェア）
有料外部API（Gemini API、Google Cloud Vision / TTS / STT）の過剰な呼び出し、およびDoS攻撃やバグによる無限ループ起因の破産的課金を防ぐため、バックエンドに独自の制限・自動停止ミドルウェアを実装する。

## 3.1 処理フロー

 **① API呼び出しのインターセプト**:
 バックエンドから外部有料APIをコールする共通関数（ラッパー）を作成。

 **② カウンターのインクリメント**:
 API呼び出しが成功するたびに、軽量・高速な永続化ストレージまたはインメモリDB、あるいはローカルの安全なファイルベースカウンターに、当月の累積利用金額（想定ドル/円換算値）を加算していく。

 **③ 閾値監視（サーキットブレーカー発火）**:
 ・**警告閾値(完全無料分まで)**：
  それぞれの現時点での無料枠内で開発、実装を行う。無料分が終了するとすぐにシステムの動作を止めるか、API系で動いていない分だけ動くようにする
 
 ・**絶対停止閾値**：
   閾値に達した瞬間にミドルウェアのフラ
    →SYS_CHARGE_LIMIT_EXCEEDED を True に変更。

 **④ エンドポイントの自動遮断**：
   フラグが True の間、FastAPIの全APIリクエストの入り口（ミドルウェア層）で、外部APIを伴うリクエストに対して即座に HTTP 503 Service Unavailable（カスタムメッセージ: 「API呼び出し制限に達したためシステムを一時停止しています」）を返し、外部APIへのアウトバウンド通信を完全にシャットダウンする。

### 4. エンドポイント一覧・I/O定義

| パス | メソッド | 認証 | 説明 | 入力(型) | 出力(型) |
| --- | --- | --- | --- | --- | --- |
| /api/v1/auth/callback | GET/POST | 不要 | Google OAuth連携と仮登録処理 | Google認証コード / トークン | 一時セットアップ用JWT | 
| /api/v1/auth/setup-password | POST | 必須(Setup) | Argon2idによるパスワード本登録 | パスワード文字列 (str) | 通常セッション用JWT | 
| /api/v1/auth/login | POST | 不要 | メール・パスワードによる通常ログイン | メールアドレス、パスワード | 通常セッション用JWT | 
| /api/v1/ocr/scan | POST | 必須(Session) | 薬剤説明書等の画像OCRおよび構造化パース | UploadFile (画像バイナリ) | OcrStructuredData (JSON) | 
| /api/v1/rag/translate | POST | 必須(Session) | 確定薬剤名のRAG検索・やさしい日本語変換 | 確定薬剤名 (str), 選択モード | 変換テキスト、公的出典表記 | 
| /api/v1/dictionary/sign-language | GET | 必須(Session) | 手話単語・動的指文字URLの配列取得 | 変換後やさしい日本語テキスト | 動画URLプレイリスト (JSON) | 

本ドキュメントの定義に基づき、各ブランチ（feature/api-auth-lifecycle 等）の開発を進めること。各処理において例外が発生した場合は、フロントエンドのアクセシビリティを阻害しないよう、適切なエラーコードとユーザーフレンドリーなメッセージに翻訳してレスポンスを返す構成を徹底する。
